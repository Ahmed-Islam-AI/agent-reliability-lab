# agent-reliability-lab

An evaluation platform for tool-using AI agents. It answers one question:

> If I change an agent's model, prompt, tools, guards or orchestration, does it become more reliable, and at what cost?

The platform core knows nothing about any business domain. A **domain pack** (environment, tools, policy evaluators, prompts, dataset) plugs in through `src/agentlab/contracts/`. The first pack is customer support for a fictional electronics retailer. A second pack (IT helpdesk) comes later and must need zero platform changes. Three **reliability studies** run on the platform as experiments and produce the portfolio's numbers.

Source plans are in `docs/source_plans/`: the original 3-project lab plan and the Notion guide "Build an AI Agent Evaluation Platform". This file and `specs/` are the merged spec. Where they differ from the source plans, these files win.

Owner: Ahmed. He reviews every phase and makes all git commits.

## Non-negotiable rules

1. **Never invent numbers.** Every metric in the README, results tables or resume lines comes from an exported report in `results/` produced by a real run. Tables are generated by script. If a number does not exist yet, write `TBD (run <command>)`.
2. **Platform code never imports a domain pack or a concrete agent.** Only `src/agentlab/registry.py` (the composition root) and tests import them. If the platform needs a new extension point, add it to `contracts/`.
3. **The agent never sees the evaluator view of a task** (expected outcomes, hidden fixture fields, grading rules). Tools are the agent's only way to learn facts.
4. **Every attempt gets a fresh environment** built from the task fixture. Nothing is shared or mutated between attempts.
5. **Every behavior is a switch recorded in the experiment manifest**: guards, faults, idempotency, agent mode, model, prompt, temperature. "Before" and "after" use the same code with different settings.
6. **Execution status and evaluation status are separate.** An evaluator crash is `evaluation_error`, never an agent failure or a pass. Missing token usage is unknown cost, never zero.
7. **Never rerun failed agent attempts until they pass.** Infrastructure retries are bounded and recorded. Agent failures are scored as they are.
8. **Tests never call a real LLM.** Use `ScriptedLlmClient` or `ScriptedAgent`.
9. **Secrets live in `.env`** (gitignored). Keep `.env.example` current.
10. **No new dependency** outside the stack list without asking Ahmed first and noting it in `PROGRESS.md`.

## Code standards

- **One class per file.** Name the file after the class in snake_case (`ToolGateway` → `tool_gateway.py`). This includes Pydantic models, enums, protocols and exceptions. A file may also hold plain functions that serve that same class's job. A file without a class does exactly one job (for example `bootstrap_ci.py`).
- **Simple over clever.** No abstraction with a single implementation. No config for values that never change. No wrapper layers (repository, service or manager classes over SQLAlchemy) unless a phase spec asks for one. No code "for later".
- **PEP 8**, enforced by ruff: rule sets `E, W, F, I, N, UP, B, SIM, D` (Google docstring convention; module, package, magic-method and `__init__` docstrings not required). Line length 88.
- Type hints on every function. `mypy src` passes with `disallow_untyped_defs = true`.
- Docstrings on public classes and functions: one line on what it does. Add Args/Returns only when they are not obvious.
- Pydantic v2 for every data shape that crosses a boundary: tool args, task files, API bodies, events, scores. Tool argument models use `extra="forbid"`.
- Schema fields use `typing.Annotated` with `Field(...)` for constraints and descriptions (`order_id: Annotated[str, Field(pattern=..., description=...)]`). Reused field types are `Annotated` aliases (`OrderId`, `AmountMinor`). SQLAlchemy columns use `Mapped[Annotated[...]]` aliases for repeated column types. FastAPI parameters use `Annotated[..., Query()]` / `Annotated[..., Depends()]`.
- Tools return JSON-serializable dicts, errors included (`{"error": "...", "code": "..."}`). They never raise into the agent loop.
- stdlib `logging` in library code. Rich only in the CLI. No `print` in `src/`.
- Keep files small (about 200 lines). Longer needs a reason.
- Frontend: one component per file and one hook per file, named after it (`RunTimeline.tsx`, `useExperiment.ts`). API types are generated from the FastAPI OpenAPI schema, never written by hand.

## Production standards

Production-ready means correct under failure, not more layers. Every phase keeps these:

- **The database enforces invariants.** Foreign keys, unique constraints and indexes are in the migration, not only in Python.
- **Immutable versioned inputs.** Dataset versions, task versions, agent configs and prompts are stored once with a content hash and never edited. Changed content needs a new version.
- **Idempotent writes where retries can happen.** Re-running an import or a create with the same content returns the existing row.
- **Crash-safe recording.** Trace events are persisted as they happen, so a crash leaves a readable partial trace.
- **No silent failures.** Unexpected exceptions are logged with traceback and stored as an explicit status (`infrastructure_error`, `evaluation_error`). Expected errors are typed (`agentlab.errors`) and shown to the user without a traceback.
- **Validated config.** Settings are validated at startup. Secrets use `SecretStr` and never appear in logs.
- **Migrations are tested.** Integration tests build the test database by running Alembic, not `create_all`.
- **UTC everywhere.** Timezone-aware timestamps in the database. Monotonic clock for durations.

## Stack

**Backend:** Python 3.12 with uv. FastAPI + uvicorn. Pydantic v2 + pydantic-settings. SQLAlchemy 2.0 (async) + psycopg 3. Alembic. PostgreSQL 17 in Docker Compose. LiteLLM (the only way to call a model). LangGraph (agent graphs only; platform code never imports it). Typer + Rich (CLI). PyYAML (datasets). HTTPX (HTTP agent adapter, API tests). pytest + pytest-asyncio. ruff. mypy.

**Frontend (from phase 5):** React + Vite + TypeScript, React Router, TanStack Query, Recharts, openapi-typescript (dev), CSS modules, ESLint.

**Models:**
- Now: Groq free tier through LiteLLM (`groq/<model-id>`), key `GROQ_API_KEY`. Later: a paid provider, which must be a config change only.
- Pick model ids from Groq's current model list in phase 2 (tool calling required). Store them in `.env` and agent configs. Record the provider-resolved model id on every model call.
- The free tier bills $0, so cost is **estimated** from the provider's published list price (`price_versions` table) and labeled "estimated" wherever it is shown.
- Groq limits are per organization and low on tokens per minute. Default `EVAL_CONCURRENCY=1`. Retry 429 and 5xx with exponential backoff that honors `retry-after`. LLM retries are recorded with their usage. They are never agent turns and never tool retries.

**Decided against:** Langfuse (the dashboard has its own trace viewer), BFCL (τ²-bench instead), Makefile (the CLI covers it), Kubernetes, multi-tenancy, auth (local only; the API binds to 127.0.0.1).

**Agent framework:** LangGraph, chosen over Google ADK (2026-11-18) because the platform must own every model call for cost and step accounting. An ADK agent can still be evaluated later through the HTTP adapter.

## Architecture

```
React dashboard ──HTTP──> FastAPI API ──> PostgreSQL <── Worker
                                                           │
                                          AttemptRunner ───┤
                                            ├─ AgentAdapter ─> LlmClient ─> LiteLLM ─> model
                                            ├─ ToolGateway ─> FaultInjector ─> domain tools ─> Environment
                                            ├─ EventRecorder ─> trace_events, model_calls, tool_calls
                                            └─ Evaluators (outcome, policy, trajectory, response) ─> scores
```

| Component | Job |
|---|---|
| API | Validates requests, creates experiments, serves status and results |
| Worker | Claims jobs from Postgres, runs attempts, updates status |
| AttemptRunner | Builds a fresh environment, runs the agent, snapshots final state, runs evaluators |
| AgentAdapter | One interface over scripted, LangGraph and HTTP agents |
| LlmClient | The platform's only door to models: retries, usage, cost, turn limit, events |
| ToolGateway | Allowlist, argument validation, identity from server context, faults, execution, records attempts and effects separately |
| Environment | In-memory domain state for one attempt |
| Evaluators | See privileged ground truth and score outcome, policy, trajectory and response |

## Glossary

| Term | Meaning |
|---|---|
| Domain pack | Environment + tools + policy evaluators + prompts + dataset for one business domain |
| Task | One problem: agent input, fixture, hidden evaluation spec |
| Dataset version | Immutable set of task versions with a content hash and splits |
| Agent config | Immutable mix of adapter, model, prompt version, temperature and guards |
| Experiment | Agent configs × dataset split × repetitions, with an immutable manifest |
| Run | One agent config × one task × one repetition |
| Attempt | One concrete execution of a run. A replacement after an infrastructure failure is a new attempt |
| Trace event | One ordered record: model call, tool request, tool result, lifecycle step |
| Score | One evaluator's result with status, reason code and evidence |
| Study | A pair of experiments (before/after or A/B) that answers one reliability question |
